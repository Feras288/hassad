# هندسة مشروع حصاد

## نظرة عامة

تستخدم حصاد تطبيق React أحادي الصفحة مع Wouter للمسارات وtRPC للعقود بين العميل والخادم. يستضيف Express إجراء tRPC ويستخدم Drizzle ORM للوصول إلى MySQL/TiDB. هذا التقسيم يمنع ازدواج تعريفات البيانات ويحافظ على النوع من الواجهة حتى قاعدة البيانات.

```text
React pages/components
        │ trpc.* hooks
        ▼
server/routers.ts ── authorization and input validation
        ▼
server/db.ts ── Drizzle query helpers
        ▼
drizzle/schema.ts + migrations ── MySQL/TiDB
```

## مسارات ومجالات أساسية

| المجال | واجهة العميل | الخلفية والبيانات |
| --- | --- | --- |
| المنتجات والسوق | `MarketplacePage.tsx` و`ProductDetail.tsx` | إجراءات المنتجات وكتالوجها |
| الموردون والخدمات | `ProviderProfile.tsx` و`BookingPage.tsx` | ملفات الموردين والحجوزات |
| الحجوزات والرسائل | لوحات `dashboard/` و`vendor/` | `serviceBookings` و`serviceMessaging` |
| سوق المحاصيل B2B | `ProduceMarketplacePage.tsx` و`DashboardProduce.tsx` | عروض المحاصيل وطلبات التسعير والتفاوض |
| الإدارة | `pages/admin/` | إجراءات الإدارة وإعدادات المنصة |
| الترجمة | `LanguageContext.tsx` و`i18n/english.json` | تفضيل اللغة المخزن للمستخدم |

## الصلاحيات

يفرض الوصول في الخادم لا في الواجهة فقط. تملك الإدارة إجراءات منفصلة، ويحصر المورد أو مقدم الخدمة بياناته في ملفه المرتبط. يجب أن يتحقق كل إجراء جديد من ملكية المورد أو العميل قبل القراءة أو التعديل.

## قاعدة البيانات والترحيلات

يحمل `drizzle/schema.ts` المصدر المرجعي للمخطط. عند إضافة حقل أو جدول، حدّث المخطط ثم أنشئ ترحيلاً واقرأ SQL الناتج قبل تطبيقه. بعد ذلك أضف الدوال في `server/db.ts` والإجراء الموثق في `server/routers.ts`. الملفات تخزن خارج قاعدة البيانات، وتحتفظ القاعدة بالرابط والبيانات الوصفية فقط. استخدم التوقيت UTC في الحفظ وحوّله محلياً عند العرض.

## قواعد واجهة مهمة

تصميم الجوال أولوية. يجب ألا تتجاوز عناصر الشبكة عرضها أو تتداخل مع التنقل السفلي الثابت، ولا تضع رابطاً داخل رابط. عالج حالات tRPC الثلاث: التحميل والخطأ والنتيجة الفارغة. لا تتحول واجهة الإنجليزية إلى RTL ولا تعرض أرقاماً أو شهادات غير موثقة على أنها حقائق.
