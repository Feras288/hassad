# دليل تطوير حصاد

## متطلبات البيئة

يتطلب المشروع Node.js 22 وpnpm. يثبت `pnpm install` الاعتمادات المقفلة في `pnpm-lock.yaml`. لا تعدل `node_modules` يدوياً. تعتمد المصادقة وقاعدة البيانات على متغيرات بيئة مُدارة من منصة الاستضافة ولا يجب نسخها إلى ملفات ملتزمة.

## الحلقة اليومية

| الخطوة | الأمر أو الإجراء | النتيجة المتوقعة |
| --- | --- | --- |
| بدء العمل | `pnpm install` ثم `pnpm dev` | خادم تطوير وHMR. |
| فحص الأنواع | `pnpm check` | صفر أخطاء TypeScript. |
| اختبار السلوك | `pnpm test` | نجاح اختبارات Vitest. |
| فحص البناء | `pnpm build` | ضروري بعد الحزم وإعدادات البناء وواجهات المتصفح. |
| تنسيق مقصود | `pnpm format` | يغيّر الملفات؛ راجع الفرق قبل الالتزام. |

## تعديل ميزة محفوظة

ابدأ بتحديد من يملك البيانات ومن يقرأها. حدّث Drizzle وأنشئ ترحيلاً قابلاً للمراجعة قبل كتابة الواجهة. ضع الاستعلامات في `server/db.ts` والإجراءات المتحققة في `server/routers.ts`. تستهلك الواجهة الإجراء عبر tRPC ثم تضيف حالات التحميل والخطأ والفراغ. أخيراً أضف اختباراً يغطي الصلاحية والمسار الناجح وحالة رفض مناسبة.

## فحص الأعطال

توجد سجلات التطوير في `.manus-logs/`. استخدم `tail` أو `grep` عليها بدلاً من تحميل الملف كاملاً. افحص أخطاء المتصفح بعد تعديل مسار أو مكوّن. إذا تغيرت حزمة أو إعداد تشغيل، أعد تشغيل خادم التطوير قبل الحكم على النتيجة.

## مراجعة قبل طلب الدمج

تحقق من صحة RTL/LTR والجوال، خصوصاً المسافات والتمرير وشريط التنقل. لا تستبدل البيانات الحية ببيانات محلية. لا تنشئ تقييمات أو شهادات أو عروضاً أو أرقاماً وهمية. راجع الترحيلات وشغّل اختبارات المشروع ووثق أي قيد معروف في وصف التغيير.
